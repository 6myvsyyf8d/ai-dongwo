## Task 5: 用户问题反馈流程指南

### 5.1 问题分类与处理流程

#### 阻塞型问题（立即处理）
**判定标准**：
- 功能完全无法使用（如登录失败、页面白屏、按钮无响应）
- 数据丢失或损坏（如记录保存后消失、档案信息错乱）
- 核心流程中断（如创建档案失败、授权无法 granting）
- 安全问题（如越权访问、数据泄露）

**处理流程**：
1. 立即中断当前任务（无论在做什么）
2. 直接描述问题现象，无需走 spec 流程
3. 助手优先排查并修复
4. 修复后验证并继续原任务

**反馈示例**：
> "小明妈妈账号登录失败，提示'用户名不存在'，这是阻塞问题，请立即修复"

#### 改进型问题（记录后批量处理）
**判定标准**：
- UI 不美观或不符合设计规范（如间距过大、颜色不协调）
- 文案不准确或不易懂（如按钮文字歧义、提示语模糊）
- 流程可优化（如步骤过多、交互冗余）
- 非核心功能的小 bug（如动画卡顿、边缘情况显示异常）

**处理流程**：
1. 在当前对话中描述问题，助手记录到问题清单
2. 不中断当前任务，继续执行
3. 当前迭代结束后或下次规划时，统一纳入路线图
4. 按 P1/P2 优先级排期处理

**反馈示例**：
> "速读卡的过敏源图标可以再大一点，这个不急，下次迭代处理"

#### 新需求（走 spec 流程）
**判定标准**：
- 全新功能模块（如新增"社区互动"模块）
- 现有功能的重大改造（如记录系统从表单改为纯对话式）
- 涉及多角色、多模块的联动需求

**处理流程**：
1. 使用 `/spec` 命令启动 spec 流程
2. 助手创建 spec.md / tasks.md / checklist.md 三件套
3. 用户审阅并批准 spec
4. 助手按 tasks.md 执行实施
5. 按 checklist.md 验证

### 5.2 问题反馈模板

```
【问题类型】阻塞型 / 改进型 / 新需求
【发现场景】在做什么操作时发现的（如：用小明爸爸登录后点击速读卡）
【现象描述】具体看到了什么（如：页面显示空白，控制台报错 xxx）
【期望行为】希望看到什么（如：应该显示 4 个卡片区块）
【复现步骤】如有，列出 1-2-3 步
【优先级】如明确，标注 P0/P1/P2
```

### 5.3 何时告诉助手问题

| 时机 | 适合反馈的问题类型 | 处理方式 |
|------|------------------|---------|
| **当前任务执行中** | 阻塞型问题 | 立即中断，优先修复 |
| **当前任务完成后** | 改进型问题 | 记录到清单，不中断 |
| **新迭代规划时** | 新需求 + 改进型问题批量 | 走 spec 流程 |
| **日常使用中** | 任何问题 | 随时记录，按类型分流 |

**关键原则**：
- 阻塞问题"即时反馈"，不要攒着
- 改进问题"批量反馈"，不要频繁打断
- 新需求"结构化反馈"，走 spec 流程确保完整性

# 项目开发汇总与后续路线图 Spec

## Why

项目自 2026-07-25 启动至今（7-29）已积累 42 个 commit、10+ 份设计/实施文档、26 个 JS 模块、12 个 CSS 文件。开发节奏快但缺少一次全局回顾：已交付什么、哪些文档已落地、哪些问题遗留、下一步该做什么。同时用户提出"我发现的一些问题，应该在什么时候告诉你"的流程问题，需要明确问题反馈时机与处理流程。

## What Changes

- **本次为纯文档变更，不修改任何代码**
- 汇总目前所有开发文档（设计稿 + 实施计划 + spec）的内容与落地状态
- 梳理已发现的问题清单（含端到端测试遗留、设计稿未落地、代码隐患三类）
- 制定后续开发的优先级路线图（P0/P1/P2 分层）
- 明确用户反馈问题的时机与流程（何时打断、何时记录、何时批量处理）

## Impact

- Affected specs:
  - `specs/001-lifelong-archive/spec.md`（原始总 spec，已部分实现）
  - `.trae/specs/cross-role-testing/spec.md`（已完成）
- Affected code: 本次无代码改动；后续路线图将影响多个模块
- 本次产出 3 份文档：`spec.md` / `tasks.md` / `checklist.md`，存放于 `.trae/specs/project-review-and-roadmap/`

## ADDED Requirements

### Requirement: 开发文档全景索引
系统 SHALL 提供一份覆盖所有设计稿与实施计划的索引表，标注每份文档的落地状态（已实现 / 部分实现 / 未实现 / 已废弃）。

#### Scenario: 查阅某功能的设计来源
- **WHEN** 开发者需要了解"家庭授权"功能的设计与实现状态
- **THEN** 可在索引表中找到对应文档路径、提交记录、落地状态、遗留问题

### Requirement: 遗留问题清单
系统 SHALL 维护一份结构化问题清单，按"端到端测试遗留 / 设计稿未落地 / 代码隐患"三类分类，每条包含：现象、根因、影响范围、建议优先级。

#### Scenario: 排查交接任务状态切换失败
- **WHEN** 开发者查阅问题清单
- **THEN** 可定位"交接任务状态切换"问题的现象、根因推测、影响范围、修复建议

### Requirement: 后续开发路线图
系统 SHALL 提供分层路线图，按 P0（必须）/ P1（重要）/ P2（可选）排列后续任务，每项标注依赖关系与预估工作量级别（S/M/L）。

#### Scenario: 选择下一个开发任务
- **WHEN** 当前迭代完成需要选择下一项任务
- **THEN** 路线图提供按优先级排序的候选任务列表，含依赖说明

### Requirement: 用户问题反馈流程
系统 SHALL 明确用户反馈问题的处理流程，区分"阻塞型问题"（立即处理）与"改进型问题"（记录后批量处理）。

#### Scenario: 用户在使用中发现阻塞型问题
- **WHEN** 用户发现功能无法使用、数据丢失、登录失败等阻塞问题
- **THEN** 立即中断当前任务，优先修复，无需走 spec 流程

#### Scenario: 用户在使用中发现改进型问题
- **WHEN** 用户发现 UI 不美观、文案不准确、流程可优化等改进型问题
- **THEN** 记录到问题清单，在当前迭代结束后或下次规划时统一处理

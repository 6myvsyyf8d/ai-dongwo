## 一、首页重构（#4）

### 1.1 设计目标

首页是**照护者（家长/保姆）的日常工作台**，不是信息展示页。  
核心问题：**打开首页应该先看有没有待处理的事**。

### 1.2 结构（自上而下）

```
┌──────────────────────────────────┐
│ 顶部问候区                        │
│  日期 + 「晚上好，小明爸爸」       │
│  心青年姓名 + 年龄 + 当前角色      │
├──────────────────────────────────┤
│ 📋 今日交接（3 条）               │
│  子标题：全部任务 · 按时间排列     │
│  ┌────────────────────────────┐  │
│  │ 表头：任务/发起人/接收人/状态│  │
│  │ 待处理行（微红底色）        │  │
│  │ 已完成行（删除线）×2       │  │
│  │ ✚ 新建交接任务（虚线按钮） │  │
│  └────────────────────────────┘  │
├──────────────────────────────────┤
│ 📊 今日健康速报                   │
│  子标题：3列大色块 · 一眼看到异常 │
│  ┌─────┬─────┬─────┐            │
│  │ 💬  │ 🎨  │ 💊  │            │
│  │沟通  │情绪  │医疗 │            │
│  │正常  │正常  │正常 │            │
│  └─────┴─────┴─────┘            │
│  ✓ 暂无异常预警（绿色条）         │
├──────────────────────────────────┤
│ 🏠首页  📝记录  📁档案  ⚙️管理    │  ← 底部导航
└──────────────────────────────────┘
```

### 1.3 已移除模块

| 模块 | 去向 | 原因 |
|------|------|------|
| 速读卡入口（首页大卡） | 档案页右上角 📚 小图标 | 速读卡是给外人看的，家长不需要每天看 |
| 快捷操作区（+添加记录等） | 整合到「新建交接任务」虚线按钮 | 快捷操作与 FAB/对话采集重叠 |
| 紧急联系人独立卡片 | 整合入速读卡（急救场景才需要） | 紧急联系人是急救信息，日常不看 |

## 二、速读卡定位（#10 / #12 / #14）

### 2.1 速读卡到底是什么？

**用户定义**：速读卡 = 给**不熟悉心青年的人**看的（救护人员、新接手保姆、临时照护者）。  
**家长对速读卡内容烂熟于胸，日常不需要看。**

### 2.2 速读卡的 3 个使用场景

| 场景 | 使用者 | 触发方式 |
|------|--------|----------|
| 急救 | 医护人员 / 路人 | 扫描档案码（挂绳/贴纸）→ 自动展示速读卡 |
| 交接 | 新保姆 / 临时照护者 | 家长分享链接/二维码 → 打开速读卡 |
| 打印携带 | 家长/照护者 | 档案页「📚 速读卡」→ 打印按钮 → 随身携带 |

### 2.3 入口分布（从首页移除后）

| 入口位置 | 形式 | 说明 |
|----------|------|------|
| 档案页右上角 | 📚 小图标按钮 | 家长主动打开/打印速读卡 |
| 档案码扫描后 | 自动跳转速读卡页 | 急救/交接场景核心路径 |
| 分享链接 | URL + token | 家长主动发给新接手者 |

### 2.4 速读卡内容（保持不变，含打印/复制/扫码入口）

过敏红线、紧急联系人、基本信息、行为干预建议。  
**新增：** 速读卡右上角显示档案码（可扫码直接进入档案），底部保留打印/复制按钮。

## 三、交接任务 Monday.com 风格 UI（#2）

### 3.1 当前版问题

- **折叠分组**：「分配给我的/我发起的」2 个分组，用户要点开才能看全
- **信息分散**：任务内容 + 发起/接收流向 + 状态分散在多行，要扫 3 行才能读全
- **无表头**：不知道每列是什么意思

### 3.2 Monday.com 风格核心特征

1. **结构化行（4 列对齐）**：每行 = 任务内容 + 发起人 + 接收人 + 状态
2. **表头行**：灰色小字标明列含义（任务/发起人/接收人/状态）
3. **状态药丸（Pill）**：
   - 待处理 → 黄色药丸（`#fdcb6e` 背景 + `#7d5a00` 文字）
   - 已完成 → 绿色药丸（`#d4edda` 背景 + `#155724` 文字）
4. **待处理行高亮**：未完成行加微红底色（`#fff8f8`）
5. **已完成行视觉弱化**：删除线 + 灰色文字（`#999`）
6. **取消折叠分组**：不再按「分配给我的/我发起的」分组，全部任务按时间混合展示
7. **底部虚线按钮**：「✚ 新建交接任务」

### 3.3 排序规则

默认按**创建时间倒序**（最新的任务在最上面）。  
待处理任务自动排最前（微红底色保证视觉优先级）。

### 3.4 响应式处理（窄屏）

| 屏幕宽度 | 布局 |
|----------|------|
| ≥ 400px | 4 列对齐（任务/发起人/接收人/状态） |
| < 400px | 发起人/接收人两列合并为「流向」一列，显示 👩→👨 图标流 |

## 四、记录页采集入口统一（#6）

### 4.1 当前问题

记录页有两个添加记录的入口：
1. **FAB `+` 按钮**（右下角浮动）→ 点击打开表单添加记录
2. **「💬 对话采集」卡片** → 点击进入 AI 对话式记录

问题：
- FAB 被底部导航遮挡（位置计算错误）
- 两个入口功能重叠，都是「添加记录」

### 4.2 解决方案：单一入口 + 内部双模式

```
记录页
├─ 💬 对话采集（唯一入口卡片）
│   └─ 进入后顶部 Tab 切换：
│       ├─ 💬 对话模式（当前 AI 边聊边记）
│       └─ 📝 表单模式（原 FAB 的模块化表单）
│
└─ （移除 FAB，解决遮挡问题）
```

### 4.3 实现要点

- 移除 `records.js` 中的 FAB 按钮（`<button class="fab" id="btn-add-record">`）
- 对话采集页面增加顶部 Tab 切换：「对话」/「表单」
- 表单模式复用现有的 `_renderRecordForm()` 逻辑
- Tab 切换状态保存在组件内部，不持久化

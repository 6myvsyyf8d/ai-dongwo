# 以心青年为中心的协作网络 — 设计方案

**Date**: 2026-07-28
**Status**: Draft

---

## 1. 概述

实现以心青年为中心的协作网络：家长作为起点创建档案，通过档案码邀请其他角色（老师、照护者、志愿者）加入；其他角色也可自主扫码申请加入，家长审批后自动建立授权关系。

## 2. 核心原则

- **家长是网络起点**：第一个注册，创建心青年档案，自动成为监护人
- **授权是访问开关**：授权只控制"能不能访问"，角色决定"能做什么"
- **档案码双用**：复用现有档案码，既可查看档案，也可申请加入
- **审批制**：所有加入申请必须家长审批

## 3. 入网流程

```
家长注册 → 创建心青年档案 → 生成档案码 → 分享给其他角色
                                                    ↓
老师/照护者/志愿者注册 ← ← ← ← ← ← ← ← 扫码
                                                    ↓
                                    填写申请理由 → 发送申请
                                                    ↓
                                    家长审批 → 自动建立授权
```

### 3.1 注册顺序

1. **家长**第一个注册 — 注册后创建心青年档案
2. **其他角色**后续注册 — 注册后处于"游离"状态，未绑定任何心青年
3. **政府**和管理员不受限 — 政府 viewing 宏观数据，管理员管理用户

### 3.2 游离状态处理

未绑定任何心青年的角色登录后：

| 角色 | 首页显示 |
|------|---------|
| 老师/照护者/志愿者 | 空状态 + "扫码加入心青年档案"按钮 + "输入档案码"链接 |
| 心青年 | 空状态 + "等待家长邀请"提示 |
| 政府 | 不变（看宏观数据，不需要绑定） |
| 管理员 | 不变（管理后台） |

**老师/照护者/志愿者的空状态页**：
- 图标 + "您还未加入任何心青年档案"
- "扫码加入"按钮 → 调用摄像头扫码
- "输入档案码"链接 → 手动输入档案码 URL

## 4. 档案码双用机制

现有档案码 URL 格式：`#archive/{youthId}?token=xxx`

### 4.1 扫码后行为

| 状态 | 当前行为 | 新增行为 |
|------|---------|---------|
| 未登录 | 提示登录 | 登录/注册后返回绑定流程 |
| 已登录-家长 | 跳转档案页 | 不变（家长看自己档案） |
| 已登录-老师/照护者/志愿者 | 跳转档案页 | **改为：进入申请页** |
| 已登录-心青年 | 跳转档案页 | 不变 |
| 已登录-已授权 | 跳转档案页 | 不变（已有权限） |
| 已登录-管理员 | 跳转档案页 | 不变 |

### 4.2 申请页内容

- 显示心青年名称（不暴露其他隐私信息）
- 显示申请者角色和姓名
- 一句话申请理由（必填，max 100 字）
- "发送申请"按钮

### 4.3 扫码后流程

1. 解析档案码 URL → 提取 youthId
2. 检查是否已有授权 → 已有则直接进档案
3. 检查是否已有 pending 申请 → 有则提示"申请审核中"
4. 未有授权且无 pending 申请 → 进入申请页

## 5. 申请审批流程

### 5.1 家长端 — 管理页新增"加入申请"入口

当有待审批申请时，管理页顶部显示红点提示。点击进入申请列表。

### 5.2 申请列表项

- 申请者姓名 + 角色图标
- 申请理由
- 申请时间
- "同意" / "拒绝" 按钮

### 5.3 审批结果

**同意**：
- 自动调用 `Permissions.grantAccess()`，按角色自动设置 scope
- 申请状态变为 `approved`
- 申请者下次进入首页时，自动看到该心青年

**拒绝**：
- 申请状态变为 `rejected`
- 记录拒绝理由（可选）
- 同一用户可再次申请

## 6. 数据模型

### 6.1 JoinRequest 实体（新增）

```javascript
{
  id: string,              // UUID
  youthId: string,         // 目标心青年 ID
  applicantId: string,     // 申请者账户 ID
  applicantRole: string,   // 申请者角色（teacher/caregiver/volunteer）
  reason: string,          // 申请理由（必填，max 100 字）
  status: string,          // 'pending' | 'approved' | 'rejected'
  appliedAt: string,       // 申请时间
  reviewedAt: string,     // 审批时间（null 表示未审批）
  reviewedBy: string,      // 审批人 ID（家长）
  reviewNote: string       // 拒绝理由（可选）
}
```

存储 key：`ai_dongwo_join_requests`

### 6.2 Storage 新增方法

- `saveJoinRequest(request)` — 保存申请
- `getJoinRequests(youthId)` — 获取心青年的所有申请
- `getJoinRequestsByApplicant(applicantId)` — 获取申请者的所有申请
- `getPendingJoinRequests(youthId)` — 获取待审批申请
- `updateJoinRequest(id, updates)` — 更新申请状态

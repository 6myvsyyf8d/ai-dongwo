# 授权管理 + 注册引导流程 设计文档

## 背景

当前系统存在以下问题：
1. "加入申请"和"授权管理"分为两个独立入口，逻辑割裂
2. "创建档案"按钮在管理页，不是初始化流程的一部分
3. 所有角色注册后直接进入空 dashboard，无引导
4. 授权范围（只读/完全访问）与角色权限存在冲突

## 核心原则

1. **一个家长 = 一个心青年档案**：注册时创建，之后不能再添加
2. **档案码双用**：既能查看档案，也能作为邀请入口
3. **授权开关模式**：授权只控制"能不能访问"，角色决定"能做什么"
4. **以心青年为中心**：所有角色围绕心青年档案建立协作关系

## 注册引导流程

### 各角色注册后行为

| 角色 | 注册后跳转 | 行为 |
|------|-----------|------|
| 家长 | `#welcome` 引导页 | 显示欢迎文案 + 创建心青年档案表单 |
| 老师 | `#dashboard` 游离态 | 显示"扫码加入心青年档案"空状态页 |
| 照护者 | `#dashboard` 游离态 | 显示"扫码加入心青年档案"空状态页 |
| 志愿者 | `#dashboard` 游离态 | 显示"扫码加入心青年档案"空状态页 |
| 心青年 | `#dashboard` 游离态 | 显示"等待家长邀请"空状态页 |
| 政府 | `#government` | 不变，直接进入 |
| 管理员 | `#admin` | 不变，直接进入 |

### 家长引导页

- 页头标题："欢迎来到 AI懂我"
- 副标题："请先创建心青年档案，开始记录之旅"（黑体，深色，17px）
- 基本信息表单：姓名、性别、年龄
- "创建档案"按钮
- 创建成功后自动跳转首页

## 管理页改造

### 改造前结构

1. 加入申请区块 → 申请审批入口
2. 档案管理区块 → 授权管理入口 + 创建档案按钮
3. 账号区块 → 用户信息 + 退出登录

### 改造后结构

1. **授权区块** → 授权管理入口（显示已授权人数 + 待审批数 + 红点）
2. **档案信息区块** → 心青年信息行（查看档案码）
3. **账号区块** → 用户信息 + 退出登录

### 关键变化

- 删除独立的"加入申请"入口，合并进授权管理详情页
- 删除"创建档案"按钮，改为注册引导页创建
- "档案管理"改名为"档案信息"，仅展示心青年基本信息和档案码入口

## 授权管理详情页

### 页面结构

1. 页头："授权管理 · {心青年姓名}"
2. **待审批申请**区块（仅当有待审批时显示）
   - 申请者头像 + 姓名 + 申请理由
   - 右侧 ✓/✕ 按钮（同意/拒绝）
3. **当前授权**区块
   - 已授权用户列表（头像 + 姓名 + 角色 + 权限说明）
   - 点击进入详情（可撤销授权）
4. 底部"添加授权"按钮（iOS 底部 Sheet）

### 授权列表项信息

- 用户头像/图标
- 姓名
- 角色标签 + 权限说明（如"老师 · 可查看全部模块"）
- 监护人标记（家长角色显示"监护人"）

### 添加授权（底部 Sheet）

- 用户选择列表（已注册但未授权的用户）
- 选中后直接授权，scope 由角色自动决定
- 调用 `Permissions.grantAccess()`

## 数据模型

### 复用现有结构

- **AccessGrant**：`ai_dongwo_access_grants` — 已有，不变
- **JoinRequest**：`ai_dongwo_join_requests` — 已在实施协作网络时新增

### 权限校验逻辑

```
用户可以访问心青年吗？
  → 有 AccessGrant 且 status = active？
    → 是：按角色权限访问
    → 否：拒绝访问
```

授权是"开门钥匙"，角色是"进门后能做什么"。

方案总览

Netlify 因部署次数过多超额。Cloudflare Pages 自带 Pages Functions，能同时托管静态文件和 API，一个平台全部搞定。

1部署到 Cloudflare Pages

两种方式任选其一。

方式 A：连接 Git 仓库（推荐，自动部署）

  1. 注册/登录 Cloudflare → 左侧「Workers 和 Pages」→「创建」→「Pages」
  2. 选择「连接到 Git」，授权 GitHub，选择项目仓库
  3. 配置构建：
    • 框架预设：None
    • 构建命令：留空（纯静态无构建）
    • 输出目录：.（根目录）
  4. 点击「保存并部署」，等待部署完成
  5. 获得域名：xxx.pages.dev
之后每次 git push 自动重新部署，无限次免费，不会再有 Netlify 的部署超额问题。
确保仓库包含 functions/api/ 目录和 _redirects 文件。Cloudflare 会自动识别 functions 目录并部署为 Pages Functions。

方式 B：Wrangler 命令行部署（无需 Git）

# 安装 Wrangler CLI
npm install -g wrangler

# 登录 Cloudflare
wrangler login

# 在项目根目录部署
cd /path/to/ai-dongwo
wrangler pages deploy . --project-name=ai-dongwo

2配置环境变量

API Key 必须配置在 Pages 环境变量中，不能写进代码。

  1. Cloudflare 控制台 → Workers 和 Pages → 选择你的 Pages 项目
  2. 「设置」→「Environment variables」
  3. 添加变量：
    • 变量名：ZHIPU_API_KEY
    • 值：你的智谱 API Key
    • 环境：选择 Production
  4. 点击「保存」
  5. 重新部署一次（环境变量变更后需重新部署才生效）
环境变量变更后必须重新部署。在「部署」列表里点某次部署的「重试部署」即可。

3验证 API 是否正常

部署并配置环境变量后，测试两个 API。

测试 chatbot（ping）

# 替换为你的 pages.dev 域名
curl -X POST https://你的域名.pages.dev/api/chatbot \
  -H "Content-Type: application/json" \
  -d '{"action":"ping"}'

# 应返回 {"ok":true}

测试 chat（心青年对话）

curl -X POST https://你的域名.pages.dev/api/chat \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"你好"}],"youthProfile":{"name":"小明"}}'

# 应返回 {"reply":"..."}
如果返回 500「未配置 ZHIPU_API_KEY」，说明环境变量没配好或没重新部署。

4清理 Netlify

迁移完成后，停止 Netlify 部署以避免继续产生费用。

  • 方案一（保留站点）：Netlify 控制台 → Site settings → 关闭自动部署。删掉 netlify/functions/ 函数。
  • 方案二（彻底删除）：确认 Cloudflare Pages 一切正常后，Netlify → Site settings → 底部「Delete this site」。
删除前务必确认新站点能正常打开页面、AI 对话能用。

验证清单

  • Cloudflare Pages 域名能打开首页，样式正常
  • 登录、档案、记录等页面可正常操作
  • 对话采集功能：发送消息能收到 AI 回复（走 /api/chatbot）
  • 心青年 AI 对话：发送消息能收到回复（走 /api/chat）
  • 环境变量 ZHIPU_API_KEY 已配置并重新部署
  • Netlify 已停止部署或已删除
